# InterviewCoach AI

A responsive interview preparation MVP built with Next.js 16, TypeScript, Tailwind CSS 4, and SQLite. Includes editable job requirements, generated practice questions, bookmarks and filters, browser voice/text practice, confirmed-transcript feedback, saved history, daily planning, and data deletion.

## Run

Requires **Node.js 24.5+** (Node 24 LTS recommended), npm, and a modern browser. SQLite uses Node's built-in `node:sqlite` module; its experimental warning is expected.

```bash
cd /workspace/-interwier
npm ci --cache /tmp/interviewcoach-npm-cache
npm run dev
```

For a production build: `npm run build`, then `npm start`. The default port is 3000; pass `-- --port 3001` to choose another port. Use the existing isolated checkout, not an additional Git worktree. Keep TLS verification and the cloud proxy enabled. Scripts enable Node's environment-proxy support for outbound provider requests.

## Providers and environment variables

Copy `.env.example` to `.env.local` and configure keys securely on the server. Never use `NEXT_PUBLIC_` names for secrets. Restart the server after changing configuration.

| Variable | Default / purpose |
| --- | --- |
| `LLM_PROVIDER` | `demo`; use `openai` for real question generation and answer evaluation |
| `LLM_API_KEY` | Optional server-only OpenAI API credential |
| `LLM_MODEL` | `gpt-4.1-mini`; must support JSON responses |
| `SEARCH_PROVIDER` | `disabled`; use `tavily` for live public search |
| `SEARCH_API_KEY` | Optional server-only Tavily credential |

Cloud network settings must allow `api.openai.com` and/or `api.tavily.com` when enabling those providers. No credentials are necessary for demo mode. Provider code lives in `app/api/coach/route.ts`; input and output are validated with Zod and provider calls have timeouts. ASR/TTS adapters live in `app/page.tsx` (`record` and `speak`). Replace these adapters to use another provider while preserving the transcript confirmation step.

### What is demo functionality?

Without credentials, job extraction matches a local skill vocabulary, questions come from role-based templates, and feedback uses simple word-count and structure heuristics. Demo feedback explicitly leaves relevance, key-point coverage, and technical correctness unassessed. Its answer outline contains placeholders instead of invented achievements. With OpenAI configured, additional role-specific questions and six-criterion feedback are generated by the model; required common questions remain available. Missing credentials and provider errors fall back to clearly labeled local functionality.

Question templates and extraction are English. AI feedback and generated role questions use the selected English/Hindi/Hinglish preference. Browser speech locale uses `en-IN` or `hi-IN`; Hinglish accuracy depends on the browser. Search results show the provider's actual URLs, titles, excerpts, and retrieval times. Excerpts are unverified source material; the app does not manufacture sources or claim any generated question is confirmed by a company. No search configuration produces an explicit empty state.

## Voice flow

1. Local NLG templates or the configured model provide a practice question.
2. Browser `speechSynthesis` reads it aloud when the user starts or chooses replay.
3. Only “Speak answer” requests microphone access. Browser `SpeechRecognition` performs ASR.
4. Stop recording, correct the editable transcript, and explicitly confirm it.
5. Submit the confirmed text for model or demo evaluation. Review feedback, retry, or move to the next question.

Text practice works without voice APIs. Denied microphone permission, recognition errors, unsupported browsers, and missing voices have usable text fallbacks. Browser recognition may send audio to the browser vendor; the app never saves raw audio. A secure browser context and a supported recognition service are required for actual microphone use. Automated validation covers the adapter flow with a mocked ASR/TTS service; actual microphone recognition requires a manual browser check.

## Persistence and privacy

`.data/coach.sqlite` stores job details, confirmed transcripts, feedback, bookmarks, and completed plan tasks. A random HttpOnly, SameSite session cookie separates browser sessions (30-day cookie lifetime; records persist until deleted). Settings → Delete all preparation data removes saved preparation records. No resumes or raw audio are stored. The preparation plan is capped at 30 days and prioritizes user-reported weak topics; feedback recommends follow-up practice.

This is a local MVP without account authentication. Add authentication, retention cleanup, deployment-wide rate limiting, and hosted storage before public multi-user deployment. API usage is limited to 30 coaching requests per browser session per hour and request/data sizes are bounded; this is not an abuse-proof public service. Uploaded documents and web excerpts must remain data rather than instructions. Resume PDF/DOCX upload and advanced company research are optional features not implemented in this MVP.

## Validation

```bash
npm run typecheck
npm test
npm run build
```

Unit checks cover job extraction, required common/role questions, honest demo evaluation, and plan scheduling. Browser checks exercised job input → corrected skills → questions → bookmark filter → confirmed text answer → feedback → persisted history → research fallback → daily completion → mobile layout → data deletion. Live OpenAI/Tavily calls are not validated without credentials. Actual browser microphone recognition must be checked manually.

For a functional smoke check, start the server, open the app, add a job description, correct the extracted skills, create the workspace, and submit a confirmed text answer. An open port alone is not readiness evidence.

The sibling handwriting recognition repository is independent. It references missing `model.pth` and `requirements.txt`; recognition cannot be validated until the trained model is supplied. This app does not depend on it.
